**Purpose:** source-level inventory for Package 1 only. This is not a data migration plan, tenant assignment, DPO/Legal approval, production authorization, or proof of deployed IAM/rules state.

## Executive finding

The baseline contains active Firebase client Firestore consumers and many Firebase Admin Firestore access paths. The dominant data model remains UID-keyed or flat/root-collection storage. The existing API verifies Firebase ID tokens with revocation checking, and selected route handlers check the authenticated UID or legacy roles. Those controls do not establish tenant membership or tenant-scoped object authorization. Firestore Rules are largely UID/participant based and Admin SDK access bypasses those Rules. No active server-side tenantContext module or authoritative legacy-record-to-tenantId mapping was found in this baseline.

All paths below are therefore not tenant-isolated by evidence in this inventory. No default tenant is inferred. A future mapping must be independently approved and prove each record's owner, tenant, lifecycle, legal hold and Art. 17 relationships. Ambiguous or ownerless records must remain unmapped/quarantined; Package 1 does not create such a quarantine or access live data.

## Review-status semantics

- **VERIFIED** — repository source file, access operation and referenced path/family were confirmed at the stated baseline. It does not mean the control is tenant-safe or production IAM was independently verified.
- **UNMAPPED** — source path is verified, but no authoritative tenant key/mapping is established by the inspected code. UID, pair IDs, provider IDs, pseudonyms, city, or an untrusted request hint are not interchangeable with tenantId.
- **[TO VERIFY]** — runtime/deployment identity, full ownership semantics, retention/legal classification, dynamically selected collection names, historic records, or DPO/Legal decisions require evidence outside this source review.

Classification labels below are a technical working classification, not a formal records-of-processing determination. DPO/Legal must confirm them.

## Method and coverage boundary

Reviewed the exact baseline tree and source hits for Firebase Web SDK (firebase/firestore, firebase/storage), Firebase Admin SDK (firebase-admin/firestore, firebase-admin/storage), getFirestore, getStorage, collection/document path construction, and known Art. 17 collections. Inspected the files and line ranges referenced below, including the API bootstrap, functions entry points, retention helpers, deletion cascade and existing security rules.

The inventory records concrete code paths discovered by this review. Dynamic path constants, runtime-configured collection names, unreferenced legacy exports, deployed Functions/IAM bindings, Firestore indexes/TTL policies, and all historic records cannot be established from source alone and remain [TO VERIFY]. Old Draft PRs #253, #287 and #288 were not used as sources. No Firestore/Storage query, emulator, staging or live migration/dry-run was run as part of this inventory.

3.
