# Production Runbook

## Preflight

1. Protect `main`, release tags, and the `production` environment.
2. Require green CI, two-person approval, CODEOWNERS review, and immutable image digests.
3. Configure runtime credentials through a secret manager and Workload Identity.
4. Configure Firebase, Stripe, Gemini, SendGrid, verification providers, `KLAR_ALLOWED_RETURN_ORIGINS`, `TRUST_PROXY_HOPS`, and a high-entropy `METRICS_TOKEN`.
5. Configure alerts from `ops/slo.json`, centralized log retention, backup schedules, and quarterly restore drills.
6. Activate and verify TTL policies with `scripts/configure-retention.sh`.

## Release

1. A semantic-version tag runs the gated release workflow.
2. CI produces source checksums, a CycloneDX SBOM, and a provenance-enabled container in GHCR.
3. Review `container-digest.txt`, `container-inspect.txt` and `deploy/cloud-run.json` / `deploy/service.json` in the release evidence. The workflow renders both manifests with the exact digest produced by Buildx and verifies that registry reference. These JSON documents are Cloud Run service manifests; choose the intended service explicitly.
4. Supply that verified `@sha256` image reference to `scripts/deploy-prod.sh`. Do not deploy the source files under `deploy/templates/`: they intentionally have no image and are not release artifacts. `npm run check:deployment` blocks ambiguous root manifests and unresolved deployment values.
4. The script creates a no-traffic candidate revision, checks liveness/readiness, and sends 10% canary traffic.
5. Observe availability, P95 latency, 5xx rate, messaging, AI dependency health, and safety signals for the approved window.
6. Promote explicitly or execute `scripts/rollback-cloud-run.sh` with a known-good revision. Never roll back by rebuilding source or deploying a mutable tag.

## Runtime signals

- `/api/health`: process liveness; contains no internal state.
- `/api/ready`: dependency readiness; returns 503 when Firestore is unavailable.
- `/api/metrics`: Prometheus text protected by `Authorization: Bearer $METRICS_TOKEN`.
- `X-Request-ID`: accepted only in a constrained format or generated by the server.
- SIGTERM/SIGINT: stops accepting connections and allows up to 25 seconds for draining.

## Rollback drill

Use `scripts/rollback-cloud-run.sh` to shift 100% traffic to an existing known-good revision. The script refuses to run without `KLAR_CONFIRM_ROLLBACK=rollback`, verifies that the target revision belongs to the configured service, performs `/api/health` and `/api/ready` checks after the traffic switch, and writes a JSON evidence record under `rollback-evidence/` by default.

A successful scripted rollback is still not production evidence until the exercise records the approved window, operator/reviewer, trigger, measured recovery time, SLO state, and resulting revision in the release evidence.

## Incident and recovery

Follow `docs/INCIDENT_RESPONSE.md`. Use feature kill switches first when containment does not require a full rollback. Restore only through `scripts/restore-firestore.sh` and the process in `docs/BACKUP_RESTORE.md`.

## Evidence required for production readiness

- Green CI and E2E run URLs
- release checksums, SBOM, image digest, and build provenance
- production approval record
- canary observation and promotion/rollback record
- latest backup and restore-drill evidence
- SLO dashboard and alert test
- incident on-call owner and escalation path
