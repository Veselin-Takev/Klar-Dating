## Reviewed control evidence (not universal assurances)
- **Client biometric boundary:** `storage.rules` denies all Firebase client reads/writes/deletes on `verification/`; Admin SDK bypass and IAM must be independently validated.
- **Profile access policy:** server-owned Firestore `users/{uid}` age and status gates rather than mutable client age / unissued JWT claims; 8 MiB maximum and restricted image MIME on writes. Download-URL bearer artifacts are not neutralized merely by these Rules.
- **Compliance endpoint:** `complianceStorage.ts` has a timestamp-bounded HMAC SHA-256 check with `timingSafeEqual`, minimum secret length, generation precondition and hold check. This is code evidence, **not** proof of secret rotation, HTTP entrypoint authorization or exactly-once deletion under distributed races.
- **Firestore RBAC:** `firestore.rules` relies on Firebase Auth custom claims; protected partner collections are denied for direct client access. Validate all nested paths and Admin SDK permissions separately.
- **TTL rollout protection:** 20-group, staging-only approved apply path, default dry-run, existing policy preflight. Still requires live ACTIVE evidence and legal review.
- **CI:** successful job and real local emulator execution, but no independently confirmed real staging/production authorization or revocation proof.

## Priority remediation and acceptance sequence
1. **P0 release stop:** lock NO-GO, inventory deployed verification-photo schedulers and retention behavior; reconcile pending/moderated state and generation safeguards in approved stage. Preserve production and privacy hold state.
2. **P1 media boundary:** inspect `storage.rules` null-evaluation warning context and negative tests; test source-path getBlob browser CORS in staging; inventory and later authorize old-token revocation separately.
3. **P0 privacy/TTL:** obtain approved 20-group retention/legal-hold matrix; fetch read-only policy evidence per environment; check Art.17 cascade and repeat/retry/rollback behavior.
4. **P0 trusted business events:** prove signed callback source, buyer provenance and concurrency/replay protection in staging plus DPO partner consent/deletion.
5. **Supply chain & governance:** verify exact final SHA and dependencies, SAST/SCA, SBOM, provenance, CODEOWNERS rules and mandatory independent reviews. Run no duplicate CI until needed and budget-approved.
6. **Human release decision:** Security + DPO/Legal + SRE/Operations + Product/Finance as applicable + Release Owner signed evidence in issue #8; otherwise **NO-GO**.
